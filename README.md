\# Прогнозирование спроса на велопрокат (BikeSochi)



Почасовой прогноз спроса на велосипеды для оптимизации логистики велопроката.

Нелинейные модели (kNN + Decision Tree) с.feature engineering против линейного бэйзлайна компании.



\## Главные результаты (тестовая выборка, один прогон)



| Модель | MAE | RMSE | R² |

|---|---|---|---|

| Baseline: линейная регрессия | 312.60 | 411.56 | 0.5861 |

| \*\*Финал: оптимизированный kNN + FE\*\* | \*\*199.33\*\* | \*\*297.98\*\* | \*\*0.7830\*\* |



\*\*Эффект:\*\* MAE −36.2%, RMSE −27.6%, объяснённая дисперсия +20 п.п.



\### Сравнение моделей на кросс-валидации (5 фолдов, train)

|---|---|

| Baseline (линейная регрессия) | 412.53 |

\## Методология по этапам



1\. \*\*Бэйзлайн.\*\* Загрузил готовый `.pkl` линейной регрессии компании, посчитал MAE/RMSE/R² на train и test — точка отсчёта для всех улучшений.

2\. \*\*EDA.\*\* Пропуски 210–263 в метео-признаках; асимметрия таргета (skew 1.156, выбросы до 3556); нелинейности: пик спроса при +20…+28°C, пороговое обрушение спроса при дожде, вечерний пик 18:00–22:00 (\~1200 аренд/час); корреляции Phik (Solar Radiation 0.74, Seasons 0.70, Temperature 0.57) и мультиколлинеарность Temperature ↔ Dew point 0.91.

3\. \*\*Feature engineering.\*\* Кастомный трансформер `EnhancedFeaturePreparer` (sklearn-API): нормализация имён колонок (пробел в `Time\_Period\_Late Evening`), восстановление скрытого периода `time\_period\_daytime`, квадрат температуры `temperature\_sq` (параболический купол спроса), бинарный флаг `is\_raining` (пороговый эффект осадков).

4\. \*\*Предобработка без утечек.\*\* Всё внутри `Pipeline`: `ColumnTransformer` с разными стратегиями импутации (константа 0 для осадков и радиации, медиана для непрерывных, мода + `OneHotEncoder` для категориальных) и `StandardScaler` для метрики kNN. Импутация считается строго внутри фолдов кросс-валидации.

5\. \*\*Модели и Optuna.\*\* kNN: `n\_neighbors=10, weights='distance', p=1` (манхэттенская метрика); Decision Tree: `max\_depth=10, min\_samples\_split=5, min\_samples\_leaf=16` (борьба с переобучением). Лидер выбран по CV RMSE.

6\. \*\*Финал и сериализация.\*\* Обучение лидера на всём train, единственный честный прогон теста, сохранение `best\_bike\_sharing\_pipeline.pkl` + тест воспроизводимости (предсказания загруженной модели совпадают на 100%).

7\. \*\*Интерпретация.\*\* Permutation Importance (kNN, test): температура, вечерний период, `Functioning Day`. Feature Importances (DT, train): скорость ветра, ночной период, точка росы — модели смотрят на данные под разными углами, что подтверждает устойчивость выводов.



\## Данные



Объём: 7008 строк × 16 колонок (train); тест отложен и использован ровно один раз.



| Признак | Тип | Особенности |

|---|---|---|

| `Rented Bike Count` | int64 | таргет; skew 1.156, выбросы до 3556 |

| `Temperature`, `Dew point temperature` | float64 | без пропусков; корреляция 0.91 (мультиколлинеарность) |

| `Humidity(%)`, `Wind speed (m/s)`, `Visibility (10m)`, `Solar Radiation (MJ/m2)`, `Rainfall(mm)`, `Snowfall (cm)` | float64 | пропуски 210–263; осадки и радиация импутируются нулём (физический смысл), остальные — медианой |

| `Seasons`, `Holiday`, `Functioning Day` | object | категориальные, OneHotEncoder |

| `Time\_Period\_Morning / Evening / Late Evening / Night` + восстановленный `daytime` | bool | бинарные флаги времени суток, OneHotEncoder |

\## Рекомендации для BikeSochi



1\. \*\*Интеграция в логистику:\*\* подключить `best\_bike\_sharing\_pipeline.pkl` к системе управления запасами — раз в сутки модель выдаёт матрицу спроса на 24 часа по свежему метеопрогнозу.

2\. \*\*Релокация парка:\*\* к вечернему пику 18:00–22:00 превентивно стягивать грузовики к станциям избыточного возврата (набережные, парки) и увозить велосипеды на дефицитные утренние точки (транспортные узлы).

3\. \*\*Дождливые периоды:\*\* при `is\_raining = 1` спрос обнуляется — сворачивать обслуживание открытых станций, персонал переводить на ремонт в ангары.

4\. \*\*Резервная модель:\*\* сохранить Decision Tree как интерпретируемую модель для обоснования решений руководству (логика «если-то»).
